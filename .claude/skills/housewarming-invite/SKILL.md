# 밍짜네 집들이 초대장

첫 초대장: https://doomoolhead.github.io/Invitations/ (저장소 `DooMoolHead/Invitations`, `main` 브랜치 GitHub Pages).
새 초대장은 이 디자인을 그대로 쓰고, 바뀌는 내용만 입력받는다. 틀은 `template/`, 빌더는 `scripts/build.py`, 입력 예시는 `examples/mingjja.json`.

## 무엇이 고정이고 무엇을 받는지

| 영역 | 처리 | 이유 |
|---|---|---|
| 맨 위 제목 `title` | 입력 | 모임마다 이름이 다름 (예: "밍짜네 집들이 초대장") |
| 제목 아래 초대 문구 `subtitle_html` | 입력 | 누구를 부르는지가 매번 다름. `<em>…</em>`은 빨간 강조, `<br>`은 줄바꿈 |
| No! 약속 `promises` | 입력, **1~5개** | 각 제목·부제목·사진(선택). 섹션 이름 "짜릿한 추억을 위한 {n} 가지 약속"의 숫자는 개수에 맞춰 자동(한/두/세/네/다섯) |
| 약속 사진 | 입력 | 한 줄에 높이를 맞춰 자동 배치, 누르면 확대·좌우 넘김. 캡션 없음 |
| 초대말 `letter_lines` | 기본 문구 고정 | 사용자가 바꾸겠다고 할 때만 줄 단위로 받아서 교체 |
| 서명 `sign` | 기본 `- 민주&찬호 -` | |
| 후보 날짜 `dates` | 입력 → 초기값 | 친구들은 되는 날을 여러 개 고르고, 과반이 되는 날을 표시. 배포 후엔 호스트 모드에서 추가·수정·삭제 |
| 오시는 길 | 고정 (`template/config.js`) | 동탄2신도시호반베르디움22단지 2202동 404호, 주차, M4137·6002 노선 링크, GTX·SRT 동탄역 픽업. 이사하면 이 파일만 고치면 됨 |
| 참석 폼·투표 현황·참석자 카드·호스트 모드 | 고정 | |

## 진행 순서

### 1. 한 번에 묶어서 물어보기
대화에서 이미 나온 건 다시 묻지 않는다.
- 제목, 제목 아래 초대 문구(강조할 단어)
- 약속 개수와 각각의 제목 / 부제목 / 사진
- 후보 날짜
- 초대말: 기본 문구를 보여주고 그대로 쓸지
- 폴더 이름(영문·숫자, 예: `2028-spring`). 새 초대장은 **같은 저장소의 하위 폴더**로 배포한다. 이미 보낸 링크(루트와 다른 폴더)는 덮어쓰지 않기 위해서다.
- 호스트 비밀번호. 저장소가 공개라서 파일에 남기지 않는다. 빌드할 때만 쓰고, `invite.json`도 저장소에 올리지 않는다.
- 카톡 썸네일로 쓸 사진(주인공이 가운데 오게 자름)

### 2. 사진 준비
- 받은 사진을 작업 폴더(`invite.json` 옆 `photos/`)에 복사한다.
- **모자이크는 사용자가 요청한 사진에만** 한다. 요청받으면 사진을 직접 보고 영역을 정한다.
  - 좌표는 사진 크기 대비 비율 `[x0, y0, x1, y1]`(0~1)
  - 세기는 `light`(아는 사람은 알아봄) / `medium` / `strong` / `heavy`(완전히 가림)
  - 처리한 부분을 잘라 직접 확인한 뒤, 사용자에게 보여주고 세기를 조절한다.
- 한 줄 안에서 한 장만 유난히 세로로 길어 줄이 높아지면 그 사진에 `"ratio": 0.75, "position": "50% 60%"`를 준다(비율 맞춰 살짝 자름, 확대 보기에선 원본).

### 3. invite.json → 빌드
`examples/mingjja.json` 형식대로 쓴다. 사진 경로는 json 파일 기준 상대 경로다.
`site_url`은 `https://doomoolhead.github.io/Invitations/<폴더>/`로 쓴다. 카톡 썸네일 주소가 여기서 만들어지기 때문이다.

```bash
python3 scripts/build.py invite.json <저장소>/<폴더>
```

- `<저장소>/<폴더>/`: 올릴 사이트(index.html, config.js, js 3개, photos/, og.jpg)
- `<저장소>/<폴더>.apps-script.gs`: 비밀번호가 들어간 구글 시트 코드. **저장소 밖으로 옮긴 뒤** 사용자에게 파일로 보낸다. 커밋되면 누구나 응답을 지울 수 있게 된다.

### 4. 확인
Playwright로 390px 폰 화면을 캡처한다. 콘솔 에러, 가로 스크롤, No! 밑선 정렬, 사진 줄 높이를 본다. 사용자에게 미리보기를 보여준다(아래 "수정 받기").

### 5. 구글 시트 연결 (사용자가 직접)
초대장마다 새 시트를 쓴다. 이전 집들이 응답과 섞이지 않게 하기 위해서다.
1. sheets.new → 확장 프로그램 → Apps Script → 받은 코드를 통째로 붙여넣기 → 저장
2. 배포 → 새 배포 → 웹 앱 / 실행: 나 / 액세스: **모든 사용자**(그냥 "모든 사용자"여야 함) → 권한 허용(고급 → 이동)
3. 받은 `…/exec` 주소를 `endpoint`에 넣고 다시 빌드·배포

나중에 코드만 바꿀 땐 "새 배포"가 아니라 **배포 관리 → ✏️ → 새 버전**으로 한다. 그래야 주소가 그대로다.

### 6. 배포
- **git이 되는 환경(Claude Code):** `Invitations` 저장소 `main`에 커밋·푸시한다. 1~2분 뒤 Pages에 반영된다.
- **git이 없는 환경(claude.ai 채팅):** 사이트 폴더를 zip으로 보내고, 업로드 방법을 안내한다. GitHub 저장소 → Add file → Upload files에서 폴더째 끌어다 놓고 Commit하면 된다.
- 링크와 썸네일을 전달한다. 폰에 예전 화면이 보이면 링크 끝에 `?2`를 붙여 열어보라고 안내한다(js 파일엔 자동으로 버전 꼬리표가 붙음).
- 클라우드 환경에선 github.io·script.google.com 접속이 막혀 있을 수 있다. 그럴 땐 실제 동작은 사용자 폰으로 확인받는다. 로컬에선 Apps Script를 Node `vm`에 SpreadsheetApp·ContentService·LockService·PropertiesService 스텁으로 붙여 폰 두 대 시나리오(등록 → 다른 폰에서 보임 → 호스트 삭제·날짜 저장)를 돌려 검증한다.

## 수정 받기

사용자는 화면을 보며 짧은 댓글로 고치는 방식을 좋아했다. 미리보기 아티팩트(claude.ai)를 올리고, 댓글이 오면 고쳐서 같은 주소에 다시 올리고, 스레드에 한 줄로 답한다. 공개 사이트에도 같은 수정을 반영한다.

## 디자인 규칙 (첫 초대장 때 사용자가 직접 요청한 것들)

- "No!"와 제목은 **글자 밑선을 맞춘다**(No!에 `top:3px` 보정). 둘 사이 간격은 좁게(첫 칸 56px).
- 부제목은 제목 **바로 아래** 붙인다.
- 편지 글씨는 **줄 위에 올라앉게** 한다(줄 간격 36px, padding-top 9px). 서명도 한 줄을 차지한다.
- 사진 아래 캡션은 넣지 않는다. 흰 틀은 사진에 딱 맞게(사방 6px).
- 버튼 문구: 누르기 전 "등록", 누른 뒤 "등록완료!"
- 정류장 링크 밑줄은 파란색, 버스 번호는 빨간 꼬리표.
- 차량번호는 가리지 않고 전체 표시.
- 모이는 시간은 정하지 않고 "모이는 시간은 자유", 투표 마감 없음.

## 파일

- `template/index.html`: 페이지 틀. 치환자 `{{TITLE}}` `{{SUBTITLE_HTML}}` `{{PROMISES_LABEL}}` `{{PROMISES_HTML}}` `{{LETTER_HTML}}` `{{OG_DESC}}` `{{SITE_URL}}` `{{YEAR}}` `{{VERSION}}`
- `template/config.js`: 오시는 길(고정), 호스트, 날짜, 시트 주소
- `template/rsvp.js` `form.js` `lightbox.js`: 데이터, 폼·현황·호스트 모드, 사진 확대
- `template/apps-script.gs`: 구글 시트 백엔드(비밀번호 자리 `'여기에-비밀번호'`)
- `scripts/build.py`: 빌더(Pillow 필요)
- `examples/mingjja.json`: 첫 초대장 입력값(형식 참고용)
